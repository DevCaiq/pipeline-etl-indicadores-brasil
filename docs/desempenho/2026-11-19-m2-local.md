# Desempenho M2 — ensaio sintético local de 19/11/2026

Registro da medição inicial. A latência sem cache foi posteriormente corrigida:
p95 de 158,75 ms sem cache e 126,87 ms com cache, ambas as metas atingidas.
Ver [investigação e novo benchmark](2026-11-19-otimizacao-sem-cache.md).

Benchmark executado com **um milhão de observações simuladas** em banco separado.
A medição foi concluída com integridade preservada; a **meta sem cache não foi
atingida**. A meta com cache foi atingida nesta mistura de consultas repetidas.

## Resultados HTTP

30 segundos de aquecimento e 60 segundos de medição por modalidade, dez clientes,
um worker Uvicorn e páginas solicitadas de cem itens. Ordem fixa: sem cache,
depois Redis exclusivo. A duração inclui a drenagem das requisições iniciadas.

| Métrica | Sem cache | Com cache |
|---|---:|---:|
| Requisições medidas | 788 | 8.754 |
| Duração com drenagem | 60,462 s | 60,047 s |
| Vazão | 13,03 req/s | 145,79 req/s |
| p50 | 747,17 ms | 62,58 ms |
| p95 | **1.093,60 ms** | **108,58 ms** |
| p99 | 1.389,35 ms | 156,25 ms |
| HTTP 200 | 788 | 8.754 |
| HTTP 429 / 5xx | 0 / 0 | 0 / 0 |
| Erros de transporte / validação básica | 0 / 0 | 0 / 0 |
| Meta p95 | até 500 ms: **não atingida** | até 250 ms: **atingida** |

| Cenário simulado | Itens | p95 sem cache | p95 com cache |
|---|---:|---:|---:|
| Primeira página | 100 | 1.093,60 ms | 105,72 ms |
| Página central, deslocamento equivalente 1.200 | 100 | 1.145,29 ms | 101,80 ms |
| Última página, deslocamento equivalente 2.400 | 100 | 1.025,69 ms | 103,06 ms |
| Agregados mensais | 83 | 1.145,02 ms | 118,78 ms |

O contador exclusivo da API comprovou, durante os 60 segundos medidos:
788 cálculos e zero acertos sem cache; 8.754 retornos cacheados e zero cálculos
com Redis. A soma coincidiu com os pedidos HTTP nas duas modalidades.
Consultas de autoridade/geração ao PostgreSQL continuam acontecendo nos acertos.

O Redis iniciou vazio e teve 26 chaves, zero expulsões, 13.221 acertos e 26
ausências no INFO durante o ensaio inteiro, incluindo preparação e aquecimento.
Esses contadores INFO não são taxa de acerto de respostas HTTP. As quatro
consultas medidas são repetidas, com alta reutilização; os 100% de acerto da
janela aquecida não representam qualquer distribuição real de acessos.

## Dataset, ambiente e reprodução

- 400 séries simuladas, 2.500 datas por série: 01/01/2020 a 04/11/2026.
- Semente `20261119`, valores exatos `numeric`, fórmula no
  [protocolo M2](protocolo-m2.md). Catálogo identificado com `SIMULADA`.
  Código 432 reutilizado somente nesse banco; os valores não são Selic real.
- Banco `etl_benchmark_m2_20261119_165126_db457c`, 127.220.759 bytes após preparo.
- Windows, Intel Core i5-3470 @3,20 GHz, quatro núcleos; RAM 33.754.714.112 bytes.
  Docker engine 29.9.3/WSL, quatro CPUs, RAM efetiva 16.471.650.304 bytes.
- PostgreSQL 16.16, Redis 7.4.12, Python 3.12.3, FastAPI 0.165.0,
  Uvicorn 0.54.0, SQLAlchemy 2.0.58, psycopg 3.3.9, HTTPX 0.28.1,

  da medição. Definições reais dos índices e SHA-256 de 68 arquivos de

- Gerador e API compartilham a máquina; os serviços locais de monitoramento

## Planos SQL

Dez EXPLAIN ANALYZE BUFFERS por estratégia/posição; mesmas linhas conferidas,
LIMIT 101, após aquecimento HTTP. Tempos medianos de Execution Time:

| Posição | Deslocamento | Linhas | Keyset | OFFSET |
|---|---:|---:|---:|---:|
| Início | 0 | 101 | 0,115 ms | 0,119 ms |
| Meio | 1.200 | 101 | 0,156 ms | 0,997 ms |
| Fim | 2.400 | 100 | 0,196 ms | 4,210 ms |

Esse recorte SQL mede uma série de 2.500 registros em banco de um milhão de fatos.
Não demonstra paginação de um milhão por série nem explica sozinho a latência
HTTP. A resolução de série passa pelo catálogo completo na implementação atual;
esse caminho é um ponto para investigar antes de atribuir a causa do atraso.
Não foi feita otimização da aplicação nesta etapa para obter um resultado favorável.

## Integridade e pendências

SHA-256 e contagens das 23 tabelas/MVs core/ops/mart sintéticas coincidiram
antes/depois. Retrato da origem real BCB/IBGE também permaneceu igual.
Servidores próprios encerrados; remoção do único Redis temporário confirmada por
rótulo exclusivo. Banco sintético preservado, sem publicação externa.

Revisão independente levou à instrumentação específica de cache, limpeza
verificável e identificação precisa do esquema/código. 478 testes passaram,
cobertura 94,75%; Ruff, formatação dos arquivos novos e mypy aprovados.

O ensaio preliminar foi substituído por esta execução revisada como evidência
principal. Ordem fixa, buffers aquecidos e carga fechada não medem saturação,
disco frio, todas as rotas M2 ou SLA de hospedagem. IBGE não compõe essa mistura HTTP.

Este resultado inicial motivou a investigação e melhoria referenciada acima. M2 ainda tem
S3/MinIO, agenda IBGE, instrumentação complementar e demonstração completa a
concluir. M3 e GitHub continuam adiados.
